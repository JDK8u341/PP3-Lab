# R10-R13：从值链到独立记录

你的伪链表展示了一个此前图模型没有强调的点：**一次追加只需建立局部的短路径，不必让整张图最终通向零。**这个思路可以保留，再把“节点身份”和“节点数据”拆开，就能处理重复值和零数据。

## 原构造：值本身兼任节点地址

令 `f(a)=memory[a]`。初始化 `&-1 ^2` 得到 `memory[0]=-1`，表头槽 `memory[-1]` 仍为 0。之后每个非零输入 x 执行 `^3 ^2`：

1. `^3` 从 x 出发：未占用节点满足 `f(x)=0`，再由 `memory[0]` 到旧尾 t，所以写 `memory[t]=x`。
2. `^2` 从 x 经默认的 `memory[x]=0` 写入地址 0，所以令 `memory[0]=x` 成为新尾。

链表首节点保存在 `memory[-1]`，尾地址保存在 `memory[0]`。以 `~1` 沿 `memory` 读取后继，直到 view=0 停止。输入 `5,6,7` 后：

```text
memory[-1] = 5
memory[5]  = 6
memory[6]  = 7
memory[7]  = 0
memory[0]  = 7
```

追加本身不随已有链长度增加：`^3` 和 `^2` 是固定两条指令，寻找旧尾不需要遍历，因为它由 0 槽直接记录。这就是局部路由：新节点先连到当前尾，再更新尾指针。

但节点身份等于值，所以同一值不能表示两个节点。插入 `5,5` 会令 `memory[5]=5`，形成自环。值 0 是结束哨兵，不能作为数据；-1 占用表头槽，也不能使用。其他负数在空白运行器中可用，但在复杂程序里可能与已有负地址槽碰撞。完整约束和有限反例见 `examples/value-chain.pp3` 与相应测试。

## 独立记录：身份与载荷分离

为支持重复值，将每个节点改成一段记录。堆从 `array_base` 开始向更负方向分配，每条记录跨度 4：

| 地址 | 字段 | 内容约束 |
| --- | --- | --- |
| R | 永久零头 | 始终为 0，作为路径锚点 |
| R-1 | 幅值 | 自然数 |
| R-2 | 符号 | 0 为非负，1 为负 |
| R-3 | 后继引用 | 0 或下一条记录的地址 |

引用变量保存记录地址；负数载荷不作为地址存储，负零输出时规范化为零。因而两个幅值和符号完全相同的记录仍有不同地址。

Bump 指针是下一条未分配记录的地址，每次递减 4。回收的记录压入空闲链；后续分配优先弹出空闲头，空闲链耗尽才移动 bump。逻辑释放不会缩小 `defaultdict`，物理字典条目可能保留。

此实验目前只允许一个堆布局，不与普通交错 Tape 共用地址区。程序初始化只运行一次；复用 heap 前须清空所有持有旧引用的链表。

全部宏和临时槽必须在运行前静态生成。`compile_program` 两遍构造代码后才确定堆起点；不得在活动堆旁边不断生成新的变量或分支标志而不重新规划区域。混合操作测试也先生成一次追加/弹出代码，再在同一运行器上反复执行，而非运行时扩张静态布局。

## 分类型路径：引用短，载荷稍长

这不是让全部地址采用同一个深度。引用值只允许 0 或记录头 R，而 `memory[R]=0`，所以引用到零最多一步，引用槽和后继字段可以采用深度 3 的自环写入。

设引用变量位于 P：

```text
&0 ^1 &P ^3 &P ^1 EXPRESSION ^3
```

从 P 经旧引用到零，写出 `memory[0]=P`；建立 P 自环后，新引用从 R 经零到 P，或从零直接到 P，再用自环补齐，因此正确存入。后继推进不能先清旧引用，改用交换：

```text
&0 ^1 &P ^3 &P *1 @- @- @- ~1 ^3
```

交换把旧记录地址 R 取到 view，同时给目标 P 建立自环；减三后读取 `memory[R-3]` 得下一引用，再写回。前置条件是 P 当前非空；零引用不允许减三作字段地址。

幅值和符号是自然数，可能经过正地址的集合标记再到零，最多两步，因此载荷字段使用深度 4。字段地址通过记录引用加固定偏移得到，不取决于逻辑链表有多长。这里的零头是独立的路由字段：只用于保证引用路径，不和真正的 next 字段混用。

## 记录队列、栈与局部路由

每个容器同时保存 head 和 tail 两个引用槽。空链统一满足二者为 0。

- 队尾追加：非空时只写旧 tail 的 next，再替换 tail；空时 head、tail 同时指向新节点。
- 头部插入：令新节点 next 指向旧 head，必要时初始化 tail，再替换 head。
- 弹出头：取走 head，head 前移；若新 head 为零，同时清空 tail。
- 释放：节点必须已经从活动链摘下，再把它接到 free 链。

追加的前置条件是节点非空且已经与其他活动容器分离，其 next 为零；弹出头仅用于非空的线性链；空闲节点必须由分配器重新初始化后才能再次附加。

所有追加/弹出都有分支，但 handler 分派数是常数，不随链长变化。比较不同长度的真实耗时仍可能受整数表示、字典、内存访问和分支影响；“O(1)”这里特指 PP3 宏调用/分派规模，而不是说宿主操作的物理成本严格恒定。

## O(1) 拼接依赖所有权转移

有 tail 槽的非空链表可直接令 `tailA.next=headB`，然后 `tailA=tailB`；若 A 为空，则直接接管 B 的 head/tail。操作不逐节点移动，因此分派数不依赖两条链的长度。

拼接后 B 的 head/tail 清零，所有权转移给 A。前置条件是两表使用同一 heap、控制槽不同、节点集合不重叠，而且调用方之后不再把旧 B 引用当成活动链。当前宏拒绝同一列表对象，但无法在 PP3 内自动检测任意节点重叠；违反所有权规则可能产生环或双重释放。

## 有向环与已知基数遍历

把 tail.next 指回 head 后，链中没有零终点，普通 `while reference != 0` 会永不结束。构造环之前先线性走一遍数出 n，再闭环。随后用计数器精确走 n 次，逐节点输出。

因此，节点局部后继可以形成有向环；循环的终止来自外部的已知基数，而不是强制所有图都保持有根无环。若遍历期间插入或删除节点，旧计数不再代表恰好一圈，必须重新计算或更新计数。

必须区分原始函数图 `f(a)=memory[a]` 和逻辑后继投影 `g(R)=memory[R-3]`。环示例中 g 成环，而 f(R) 始终为 0；普通深度寻址沿 f，不会自动沿 g 绕圈。原始值链则是真正在 f 中留下 `0→tail→0` 的二元环，依靠 view=0 时退出而不继续追 0。两种技巧有不同不变量，不能混为“任意环都安全”。

## 验证与边界

自动测试覆盖原值链不同符号节点、重复值导致的环、独立记录中的重复/零/正负载荷、队列 FIFO、栈 LIFO、拼接的空/非空组合、free-list 复用、环的有限遍历，以及链结构与地址集合标记宏共存。另验证追加和拼接的分派数对不同链长相同。

记录头保持零是有意设计：数据地址到锚点的路径长度有界，字段写宏才可证明安全。记录引用不得与普通数据槽别名；同一节点不能被多个容器同时拥有；释放只能发生一次且必须先摘链。这些仍是宏契约，不是运行器强制的静态类型检查。

`record-queue/stack/splice/ring` 的输入是数量 n 加 n 个 `(符号,幅值)` 编码对，不接受直接输入裸负数。本轮解决身份与数据冲突，没有声称解决任意有符号整数的无编码读取。堆没有动态所有权检查、自动回收或多堆并存支持。
