# 反例、边界和下一步

## 正地址自环破坏有根性

测试夹具先建立：

```text
memory[-10] = 1
memory[1] = 1
```

试图用 h=2 的宏把 2 写到 -10：

```text
&0 ^1 &-10 ^4 &-10 ^1 &2 ^4
```

第一次从 -10 寻址会困在 1 的自环，反而把 -10 写入 `memory[1]`，后续也无法正确把 2 放到目标。这是算法前置条件失败的反例，不是 PP3 的寻址 bug。

因此“加深 ^n 就一定能找回 0”是错误命题：如果路径进入不含 0 的环，任何更大深度都不保证到达 0。

## 固定偏移不能解决任意负输入的地址碰撞

给所有整数加一个固定偏移 C，仍存在输入 `x=-3-C`，使 `x+C=-3` 撞到保留槽。把偏移设得很大只是改变反例，不构成对所有整数的证明。

本项目改用非负数据、符号/幅值或位串表示，不再对全部裸负输入逐一分类。但从任意裸 signed `@input` 在已有复杂内存中安全转换为该表示，尚未实现通用无枚举解。

## 原值链与记录链是不同内存协议

维护者提供的原值链允许互异的裸负数直接充当地址，但排除 0、-1；它运行于独立空白内存，不能与本项目保留零锚点和普通槽的模型不加区分地混用。

记录链将身份与数据分离，支持重复、零和编码负载荷，详见 [记录堆证明](07-linked-records.md)。它仍不等价于接收任意裸负数并在复杂内存中安全保存的通用构造。

后继字段投影出的逻辑环可以安全存在，因为原始记录地址本身仍指向零。双重释放、重复插入同一个节点、拼接重叠链表或误用零引用则可能破坏结构；目前只拒绝部分生成期可见的别名，不提供运行期所有权检查。

## 零锚点、别名与工作槽

地址 -1、-2 不能作为用户数据槽；正地址只接受规定的标记。宏的输入输出槽必须满足各自的非别名条件，内部命名工作槽留给库使用。普通 `put` 的表达式不能再读目标旧值，也不能随意执行其他写宏破坏其自环。

当前宏库不是对任意组合自动做类型检查的编译器。构造器只拒绝部分已知冲突，使用者仍需证明前置条件；不能把“当前示例通过”扩大成“任意嵌套使用都正确”。

## 原始字节和输入错误

运行器字符接口仍是按行文本输入、补 LF、EOF 抛异常。二进制示例明确按文本协议读取 0/1 行，不把输入当成原始二进制文件。

自然数示例只在非负整数定义域内验证；负输入或不合法位串可能违反内存图约束。这里没有改变语言语义去兜底，也没有把未支持输入写成已支持特性。

## 后续实验

1. 在位串表示上实现大小比较，再替换逐数抵消，避免比较接近大数时缓慢。
2. 基于位移与逐位加法实现二进制乘法，严格区分算术位数和输出长度。
3. 研究十进制字符输入到二进制带的转换，避免先累计一个巨大单槽整数。
4. 完成记录式链表的通用迭代器、删除和所有权边界，并证明不会误释放仍被引用的节点。
5. 为宏增加可检查的类型/别名契约，而非依靠约定命名。
6. 在保留原版 Runtime 的前提下发展 PP3 子集解释器；目前尚未完成自举或完整自解释。

本轮没有发现疑似上游实现 bug。现有反例都对应明确被破坏的实验不变量；如果后续出现源码行为与预期语言语义冲突，先向维护者报告，不私自修改运行器。
