# 验证方法与成本模型

## 固定实现

PP3 子模块固定为 `aceb4c532cf475f7b69fb623affc81c9f70e8c48`。全部执行使用原版 `Runtime`、`IRBuilder(op_map=std_register)`、禁用直接寻址。构建工具额外检查 IR 并拒绝直接寻址及非标准操作；没有替换内存表或循环。

Python 只在两个位置使用：编译前静态展开宏；测试端生成参考答案、输入夹具与测量。示例运行时的集合、等值、排序和二进制运算均由 `.pp3` 自身完成。

## 测试证据

- 自然数等值：0..7 的 64 对，加上 1001 位值的相等、相邻不等和零边界，检查临时正地址标记清除。
- 稀疏集合：零键、重复键、201 位键，检查已触及正地址的成员关系。
- 标记共存：先把许多常用数值地址标为成员，再运行写入、自增、自减、复制、等值和双带操作。
- 等值恢复：覆盖 x/y 是否已属于集合与二者是否相同的组合，检查原标记恢复。
- 大小比较：0..15 的 256 对以及超过字节域、巨大的相等值和零边界。
- 有符号编码比较：[-8,8]² 的 289 对以及负零。
- 比较排序：含 256 以上值、相等值、逆序、空序列和固定种子的 20 组随机序列，与独立排序比较。
- 二进制加法：短位宽全组合、随机长串、512/1024 位以及跨全长进位；Python 大整数仅作测试参考。
- 小图定理：16 个有根图的 256 次赋值验证，并单独断言正自环反例确实失败。
- 原始值链与记录堆：互异节点、重复值反例、零/符号载荷、FIFO/LIFO、空/非空拼接、free-list 复用、逻辑环，以及与稀疏集合标记共存。

记录堆还执行 120 次固定种子的追加与弹出混合操作，每步与独立队列对照，并检查活动节点、空闲节点互不重叠，所有已分配节点恰好属于这两个集合之一。所有操作先静态编译，再复用同一份 IR，避免测试中重新扩张槽位布局。当前全库共 35 项测试。

完整用例名称和当前数量以 `python -B -m unittest discover -v` 输出为准。测试覆盖是有限证据；正确性的一般理由在各篇推导中，不能仅从通过样例推断任意输入。

## 分派计数

`lab/measure.py` 用 `sys.settrace` 观察原版 `Runtime.run` 中每次进入 handler 分派的位置。它不替换运行器、不添加操作、不修改输入或内存。包括 LoopBlock 的分派，但重复计算循环条件不单独增加这一指标，各 handler 内部寻址和 Python 操作也不是逐条计入。

计数不提供耗时加速，而且跟踪本身会使宿主执行变慢。我们只用它比较固定深度和固定宏下的分派规模，不将测量公式当作真实 CPU 性能公式。

```text
python tools/measure.py
python tools/measure_links.py
```

报告记录在 `results/dispatch-counts.json`。大整数解析的 Python 十进制长度限制仍然适用；本轮测量到 1000 位，性质测试到 1001 位，没有关闭该限制或承诺无限输入资源。

`results/link-dispatch-counts.json` 隔离追加和拼接阶段，以已有 Runtime 执行指定操作，不计建链过程。原值链计数 3 包含一条 @input 和两条追加指令；记录追加/拼接不含分配。空队列与非空队列分支成本不同，结论是与链长无关的固定上界，而非所有状态都精确相同。

## 物理内存

逻辑地址跨度大不意味着开辟同样大小的连续数组，运行器使用稀疏字典。但大整数键、哈希和 `defaultdict` 的零条目都有实际代价。清除一个逻辑标记不会删除对应字典键，物理占用可能随历史访问增长。

每次测试创建新的 Runtime。共享同一份 IR 不能作为共享输入缓冲的理由；新项目不改变上游按 Runtime 隔离标准操作实例的行为。
