# R01、R02：函数图和统一写入

## 精确语义

令 `f(a)=memory[a]`。执行深度 d 的间接操作，先计算：

```text
place = f^(d-1)(view)
```

随后 `~d` 读取 `memory[place]`，`^d` 写入当前 view，`*d` 交换当前 view 与该单元。写入值与寻址起点是同一个 view，这使“拿着数据写任意变量”不能直接照搬常规汇编。

把每个整数地址看成一个结点，边 `a→f(a)` 构成函数图。未写入的单元默认指向 0。这是对源码语义的数学表示，没有额外运行时能力。

## 有限图高赋值定理

设目标地址 X 不为 0。先把 0 槽清零。假设此刻旧载荷和待写入的新载荷，都能在至多 h 次跳转内到达 0；h 可以为 0，此时载荷只能是 0。取 `D=h+2`，执行：

```text
&0 ^1
&X ^D
&X ^1
EXPRESSION ^D
```

这里 X、D、EXPRESSION 是生成前的模板参数。表达式只产生新载荷，不能依赖已经改写的目标旧值、改变寻址所依赖的图结构或破坏目标自环。

第一条令 0 成为吸收点。第二条从 X 出发，经过旧载荷，在不超过 h+1 次跳转内到 0，剩余跳转仍留在 0，因此写入 `memory[0]=X`。

第三条建立 `memory[X]=X`。求得新载荷 v 后，沿原图在不超过 h 步到 0，再一步到 X，此后在 X 自环上补齐剩余跳转。如果路径更早遇到 X，也同样被自环吸收。因此最后的写入位置必为 X，包括 v=0 的情况。

定理首先保证这一次赋值的位置正确；要让下一次也可用，还要证明新状态继续满足相同的图高约束。本项目的内存分区保证了这一点，不能把定理扩大为对任意内存的保证。

## 本项目的图高为 2

保留两个永远为零的锚点：`memory[-1]=memory[-2]=0`。普通标量槽从 -3 往更负方向分配，仅存自然数。正地址区的值只能是 0、-1，等值操作期间还允许 -2。

这些是完整宏入口/出口处的不变量。写入过程中会暂时建立目标自环；这个受控区间不得执行其他依赖原图结构的写宏，直到目标恢复为规定的载荷。

对自然数 v>0：未标记时 `v→0`，已标记时 `v→-1→0` 或 `v→-2→0`。v=0 本身已在 0。故 h=2，使用 D=4：

```text
&0 ^1 &X ^4 &X ^1 EXPRESSION ^4
```

更新旧值时用交换取回它，同时建立自环：

```text
&0 ^1 &X ^4 &X *1 @+ ^4
```

自减版本将 `@+` 改成 `@-`，但只允许正数自减，结果继续保持自然数。普通赋值会破坏 view 和 0 槽；复制会保留源槽；目标不能同时充当表达式的旧值源。

## 可组合性

临时正地址标记也指向零锚点，不增加 h，因而允许分支标志、循环计数器和数据值碰巧等于已经标记的键地址。旧版“正地址必须全部为零”的宏没有这一性质。

这不是对所有宏无条件可重入的承诺。等值、比较等复合宏有固定命名的内部工作槽，调用参数必须与工作槽互异；当前构造没有递归嵌套调用它们。宏生成期会拒绝部分显然冲突的别名，其他前置条件见具体实现。

## 验证

测试枚举三个非零结点所有出边组合，过滤后得到全部 16 个能到达 0 的有根函数图。每图测试旧、新载荷各 4 种，共 256 次赋值，并检查原图正结点保持不变。此处枚举是对定理的小规模验证，不是赋值算法在运行时枚举输入。

正自环反例见 [边界文档](05-limits.md)。图高条件不满足时，宏可能写错位置并破坏其他单元；这属于违反实验契约，不是运行器 bug。
