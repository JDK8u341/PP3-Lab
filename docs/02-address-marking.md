# R03、R04：稀疏集合与地址等值

## 把数值用作地址

对自然数键 k，用正地址 `k+1` 表示它。加一保证地址 0 始终留给寻址；不需要对键的大小或数字位数分类。

集合状态编码为：

```text
memory[k+1] = 0    不存在
memory[k+1] = -1   存在
memory[-1] = 0    永久零锚点
```

标量中的值仍是自然数。即使一个计数器的值正好是 k+1，它最多经 `k+1→-1→0` 两步到零，符合图高模型。

## 插入与删除

先将 k+1 存在普通指针变量 P 中。其值是正地址，但该变量仍属于自然数标量。要把标记 M（0 或 -1）写入 `memory[memory[P]]`：

```text
&0 ^1
&P ~1 ^3
&P ~1 ^1
&M ^4
&0 ^1
```

目标正单元原值是 0 或零锚点，深度 3 可将目标地址写入 0 槽。随后把目标变成自环。M=0 时沿 `0→目标→目标→目标`；M=-1 时沿 `-1→0→目标→目标`，都能正确写入。最后清理 0 槽。

查询只需算出 k+1 后 `~1` 读取标记，再归一化为 0/1。每次集合操作使用固定数量的 DSL 指令，空间随被触及的键数增长，而不是随最大键值增长。

## 等值需要另一种标记

单纯用“非零标记”判断 x=y 会出错：x、y 可能都是已有集合成员。所以另保留 `memory[-2]=0`，用 -2 作为临时等值标记。

等值过程：

1. 算出 x+1，记下原单元是否为集合标记 -1。
2. 将该单元临时改为 -2。
3. 读取 `memory[y+1]`，对读取值加二后做零测试。
4. 根据保存的成员标志恢复 x+1 原来的 0 或 -1。

查询结果只有三种：0 加二为 2，集合标记 -1 加二为 1，临时标记 -2 加二为 0。且系统在宏入口处不存在其他 -2 标记，因此零测试当且仅当 x=y 成立。

整个过程保留两个输入和集合的逻辑成员关系，结果写入独立的 0/1 变量。它不是通过穷举 x、y 的值域实现，也不做逐数抵消；一个固定程序处理任意位数的自然数。

## 成本的准确含义

`examples/equality.pp3` 读取两个整数并打印结果，空集合上的测量样例不论 1、10、100、1000 位，以及相等或相邻不等，都是 115 次 handler 分派。这包括输入、输出和准备代码，不是 `equal()` 宏本身精确等于 115。

其他已标记状态可能选择不同分支，因此只能一般地声称存在与数值大小无关的固定分派上界，不能把 115 当成每种内存状态的精确数值。

整数地址由 Python 的任意精度整数和字典实现。整数输入转换、加一、哈希、碰撞处理、整数相等、打印和位存储均有宿主成本，所以没有“真实耗时 O(1)”结论。

恢复逻辑内存值也不等于删除 `defaultdict` 字典项。一次临时查询后，原先不存在的正地址可能留下值为零的键；重复查询不同大数会增长物理字典。相等判断结束后还允许普通内部工作槽变化。

## 非适用情况

正地址若存任意用户数据或任意边，0/-1/-2 的三态解释不成立；零锚点不得写入；输入不能是负数。该等值宏目前不是可以对任意裸指针图使用的通用机器整数比较。
